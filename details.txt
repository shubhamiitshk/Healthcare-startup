================================================================================
                              PROJECT OVERVIEW
================================================================================

Project Name: CatchQ
Description: A clinic queue management system with web admin dashboard and
             mobile appointment booking.
Architecture: 
  - Frontend: Next.js 15 (App Router) with TypeScript
  - Backend: NestJS with TypeORM
  - Database: PostgreSQL
  - Auth: Firebase Authentication (JWT)
  - Real-time: Socket.io for live queue updates
  - UI: shadcn/ui + Tailwind CSS

Projects in Repository:
1. catchq-landing/    - Marketing landing page (Next.js)
2. clinic-backend/   - REST API + WebSocket (NestJS)
3. final-frontend/   - Admin dashboard (Next.js 15)
4. clinic-management-system/ - Legacy/incomplete version

================================================================================
                              DATABASE SCHEMA
================================================================================

DATABASE: PostgreSQL
CONNECTION: Via environment variable DATABASE_URL

================================================================================
TABLE: clinics
================================================================================
Primary Key: id (VARCHAR, UUID or manual string)
Columns:
  - id: VARCHAR (PK)
  - name: VARCHAR (NOT NULL)
  - address: VARCHAR (NOT NULL)
  - phone: VARCHAR (NOT NULL)
  - email: VARCHAR (UNIQUE, NOT NULL)
  - created_at: TIMESTAMP WITH TIME ZONE (auto)

Relationships:
  - One-to-Many with doctors

================================================================================
TABLE: doctors
================================================================================
Primary Key: id (UUID, auto-generated)
Columns:
  - id: UUID (PK, auto-generated)
  - clinic_id: UUID (FK to clinics.id, NOT NULL)
  - name: VARCHAR (NOT NULL)
  - gender: VARCHAR (NOT NULL)
  - specialty: VARCHAR (NOT NULL)
  - qualification: VARCHAR (nullable)
  - phone: VARCHAR (nullable)
  - email: VARCHAR (nullable)
  - date_of_birth: DATE (nullable)
  - experience_years: INT (nullable)
  - avatar_url: VARCHAR (nullable)
  - created_at: TIMESTAMP WITH TIME ZONE (auto)

Relationships:
  - Many-to-One with clinic
  - One-to-Many with doctor_schedules

================================================================================
TABLE: doctor_schedules
================================================================================
Primary Key: id (UUID, auto-generated)
Columns:
  - id: UUID (PK, auto-generated)
  - day_of_week: VARCHAR (NOT NULL) - e.g., "Monday", "Tuesday"
  - start_time: TIME WITHOUT TIME ZONE (NOT NULL) - format "HH:MM:SS"
  - end_time: TIME WITHOUT TIME ZONE (NOT NULL) - format "HH:MM:SS"
  - doctor_id: UUID (FK to doctors.id, NOT NULL)
  - fees: NUMERIC (default 0)
  - booking_start: TIME (default "00:00:00")
  - booking_end: TIME (default "23:59:00")
  - booking_window: BOOLEAN (default true)
  - max_queue: INT (default 5)
  - created_at: TIMESTAMP WITH TIME ZONE (auto)

Relationships:
  - Many-to-One with doctor
  - One-to-Many with appointments

================================================================================
TABLE: patients
================================================================================
Primary Key: id (VARCHAR, manual - typically phone number or UUID)
Columns:
  - id: VARCHAR (PK)
  - phone_number: VARCHAR (UNIQUE, NOT NULL)
  - full_name: VARCHAR (nullable)
  - gender: VARCHAR (nullable)
  - dob: DATE (nullable)
  - is_profile_complete: BOOLEAN (default false)
  - firebase_uid: VARCHAR (UNIQUE, nullable) - Firebase UID for mobile auth
  - created_at: TIMESTAMP (auto)
  - updated_at: TIMESTAMP (auto)

Relationships:
  - One-to-Many with family_members
  - One-to-Many with appointments

================================================================================
TABLE: family_members
================================================================================
Primary Key: id (UUID, auto-generated)
Columns:
  - id: UUID (PK, auto-generated)
  - patient_id: VARCHAR (FK to patients.id, NOT NULL)
  - name: VARCHAR (NOT NULL)
  - gender: VARCHAR (NOT NULL)
  - dob: DATE (NOT NULL)
  - relation: VARCHAR (NOT NULL) - e.g., "Son", "Daughter", "Wife"
  - created_at: TIMESTAMP (auto)
  - updated_at: TIMESTAMP (auto)

Relationships:
  - Many-to-One with patient
  - One-to-Many with appointments

================================================================================
TABLE: appointments
================================================================================
Primary Key: id (UUID, auto-generated)
Columns:
  - id: UUID (PK, auto-generated)
  - patient_id: VARCHAR (FK to patients.id, nullable)
  - family_member_id: UUID (FK to family_members.id, nullable)
  - schedule_id: UUID (FK to doctor_schedules.id, NOT NULL)
  - queue_number: INT (default 0) - position in queue
  - date: DATE (NOT NULL) - format "YYYY-MM-DD"
  - status: TEXT (default 'waiting') - enum: waiting, serving, completed, cancelled, skipped
  - source: TEXT (default 'mobile') - "mobile" or "web"
  - created_at: TIMESTAMP WITH TIME ZONE (auto)
  - updated_at: TIMESTAMP WITH TIME ZONE (auto)

Relationships:
  - Many-to-One with patient (nullable)
  - Many-to-One with family_member (nullable)
  - Many-to-One with doctor_schedule

================================================================================
PATIENTS MODULE (/src/patients)
================================================================================
POST /patients
  - Create or get existing patient
  - Body: { phone_number: "+911234567890", fullName?: string, gender?: string, dob?: string }
  - Response: { success: true, data: patient }

GET /patients/:id
  - Get patient by ID
  - Auth required (user.uid must match patient.id)
  - Response: { success: true, data: patient }

PATCH /patients/:id
  - Update patient profile
  - Body: { fullName?: string, gender?: string, dob?: string }
  - Response: { success: true, data: updatedPatient }

GET /patients/search/:phone
  - Search patient by phone number
  - Phone format: +91XXXXXXXXXX (10 digits after +91)
  - Response: { success: true, data: patient | null }

POST /patients/:id/family-members
  - Add family member to patient
  - Body: { name: string, gender: string, dob: string, relation: string }
  - Response: { success: true, data: familyMember }

================================================================================
DOCTORS MODULE (/src/doctors)
================================================================================
GET /doctors/public
  - Public endpoint - list all doctors (for mobile browsing)
  - Response: { success: true, data: doctors[] }

GET /doctors/queue
  - Get queue overview for all doctors
  - Response: { success: true, data: doctorQueue[] }

POST /doctors
  - Create new doctor (clinic admin only)
  - Auth required
  - Body: { name, gender, specialty, email?, qualification?, phone?, dateOfBirth?, avatarUrl?, experienceYears? }
  - Response: { success: true, data: doctor }

GET /doctors
  - List doctors for current clinic
  - Auth required
  - Response: { success: true, data: doctors[] }

GET /doctors/:id
  - Get doctor profile with all schedules
  - Response: { success: true, data: doctorWithSchedules }

PATCH /doctors/:id
  - Update doctor details
  - Auth required
  - Body: { name?, gender?, specialty?, email?, qualification?, phone?, dateOfBirth?, avatarUrl?, experienceYears? }
  - Response: { success: true, data: updatedDoctor }

DELETE /doctors/:id
  - Delete doctor and all schedules
  - Auth required
  - Response: { success: true }

POST /doctors/:id/schedules
  - Add availability slot for doctor
  - Auth required
  - Body: { dayOfWeek: string, startTime: string, endTime: string, maxQueue?: number }
  - Example: { dayOfWeek: "Monday", startTime: "09:00", endTime: "17:00", maxQueue: 10 }
  - Response: { success: true, data: schedule }

PATCH /doctors/:id/schedules/:scheduleId
  - Update a schedule slot
  - Auth required
  - Body: { dayOfWeek?, startTime?, endTime?, maxQueue? }
  - Response: { success: true, data: updatedSchedule }

DELETE /doctors/:id/schedules/:scheduleId
  - Delete a schedule slot
  - Auth required
  - Response: { success: true }

GET /doctors/clinic/queue
  - Get doctors with real-time queue info for clinic
  - Auth required
  - Response: { success: true, data: doctorsWithQueue[] }

================================================================================
APPOINTMENTS MODULE (/src/appointments)
================================================================================
POST /appointments/book
  - Book an appointment (mobile or web)
  - Auth required
  - Body: { patientId?: string, familyMemberId?: string, newMember?: object, scheduleId: string, date: string, source?: string }
  - Example: { patientId: "uuid", scheduleId: "uuid", date: "2024-01-15", source: "web" }
  - Response: { success: true, data: appointment }

GET /appointments/patient/:id
  - Get all appointments for a patient/family member
  - Response: { success: true, data: appointments[] }

GET /appointments/schedule/:scheduleId/:date
  - Get queue status for a schedule on a date
  - Response: { success: true, data: queueStatus }

PATCH /appointments/:id/status
  - Update appointment status
  - Body: { status: "waiting" | "serving" | "completed" }
  - Response: { success: true, data: updatedAppointment }

GET /appointments?scheduleId=&date=
  - Get appointments for a schedule on a date
  - Query params: scheduleId (required), date (required)
  - Response: { success: true, data: appointments[] }

GET /appointments/clinic?date=&doctorId=
  - Get all appointments for a clinic
  - Auth required
  - Query params: date (optional), doctorId (optional)
  - Response: { success: true, data: appointments[] }

================================================================================
QUEUE MODULE (/src/queue)
================================================================================
GET /api/doctors/queue
  - Get doctors queue for clinic
  - Auth required
  - Response: { success: true, data: doctorsQueue[] }

POST /api/doctors/queue
  - Add patient to queue
  - Auth required
  - Body: { patientId, scheduleId, ... }
  - Response: { success: true, data: appointment }

================================================================================
WEBSOCKET GATEWAY (/src/app.gateway)
================================================================================
Socket.io server running on same port as HTTP server (3000)

Events:
- emit: `queue-updated-{scheduleId}-{date}` - broadcast when queue changes
- emit: `status-update` - broadcast appointment status changes
- on: connection - handle client connections
- on: subscribe-queue - subscribe to specific queue updates

================================================================================
                              TECHNICAL IMPLEMENTATION NOTES
================================================================================

1. AUTHENTICATION FLOW
   - Web: Clinic admin logs in via email/password (Firebase Auth)
   - Mobile: Patients log in via phone OTP (Firebase Auth)
   - Backend validates Firebase JWT tokens
   - Token passed in Authorization header: "Bearer <token>"

2. QUEUE NUMBER ASSIGNMENT
   - When appointment created, queue_number = count of existing + 1
   - Or: max(existing queue_numbers) + 1

3. STATUS FLOW
   waiting -> serving -> completed
   waiting -> skipped
   waiting -> cancelled

4. REAL-TIME UPDATES
   - Socket.io connection on queue page
   - Listen to: `queue-updated-{scheduleId}-{date}`
   - Server emits on any appointment status change

5. FAMILY MEMBERS
   - Patient can have multiple family members
   - Each family member can book separate appointments
   - Family member appointments linked via family_member_id

6. SCHEDULE TIME FORMAT
   - Stored as "HH:MM:SS" in database
   - Frontend displays as "HH:MM" (slice last 3 chars)
   - Booking window: time range when online booking allowed

7. PAGINATION & FILTERS
   - Dashboard fetches 7-day trend data
   - Queue filters by doctor, day, slot
   - Billing filters by doctor, date, search

================================================================================
                              KEY BUSINESS LOGIC
================================================================================

1. PATIENT PHONE NORMALIZATION
   - All phone numbers normalized to +91XXXXXXXXXX format
   - Search strips non-digits, takes last 10 digits

2. SCHEDULE DAY MATCHING
   - Backend stores "Monday", "Tuesday", etc.
   - Frontend converts current day to match

3. APPOINTMENT UNIQUE CONSTRAINT
   - One appointment per patient/family_member per schedule per date
   - Prevent duplicate bookings

4. QUEUE REORDERING
   - On status change, maintain queue order
   - Reopening skipped patient inserts at position 3

5. FEES & PAYMENTS
   - Doctor schedule includes fees per consultation
   - Billing tracks payment status (paid/unpaid)
   - Payment modes: Cash, Card, UPI, etc.
